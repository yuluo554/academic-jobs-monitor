## 一、问题与总体方案

高校教师招聘与博士招生公告散落在各高校人事处页面与聚合平台，截止日期常埋在正文里，人工"盯官网"不可复现。本工具将其变成一条**确定性数据管道**：

```
抓取层（5 源适配器） → 抽取层（规则族 + 证据链） → 快照层（字段级 diff + 去抖）
       → 订阅层（关键词匹配 → RSS/HTML）          → 基准层（真值对账 + 变更样本）
双形态出口：jobsctl CLI（编排打印） ⧉ 本地 Web 面板（只读视图），共享同一编排函数组
```

全程**零 AI 接口依赖**：抽取靠正则规则族，未知即 `pending`，绝不臆测。技术栈 Python 3.10+、httpx、BeautifulSoup4、SQLite、FastAPI/uvicorn、PyYAML，推送与面板渲染全部标准库手写。

## 二、抓取适配器：失败隔离与原因码

**设计要点**（`src/ajm/sources/`，M2）：

- **统一协议（K5）**：每源一个独立适配器模块，实现 `fetch_list(fetcher, config) -> FetchOutcome`；注册表 `registry.fetch_all` 逐源调度，**单源抛异常被捕获降级为失败结果，不中断其他源**（有自动化测试：一源 boom，其余照常 OK）。
- **失败原因码单列**（`FailureCode` 枚举，禁止裸字符串）：`timeout / http_error / robots_disallowed / waf_blocked / parse_empty / encoding_error / unknown`。其中 `waf_blocked` 专为学术桥（阿里云 WAF）设立——**识别即降级隔离，禁止绕过**（合规红线，M1 实测记录）。
- **合规约束落在配置层**：限频 ≥3.0s/源（适配器不得调低）、UA 自标识含联系方式、robots 检查前置、raw HTML 只落 `cache/`（git-ignored，K10）。
- **回放测试（K7）**：每源脱敏 fixture 入库（`src/ajm/sources/fixtures/`），适配器测试全部离线回放，结构回归不依赖网络。

## 三、字段抽取：规则族与 pending/ambiguous 纪律

**设计要点**（`src/extract/`，M3/M4）：

- **命名规则族**：deadline 字段维护一族命名正则规则（`deadline_cn_ymd` 等 4 条，覆盖"报名截止日期：2026 年 12 月 1 日"等真实句式），命中即产出 `verified` 值 + 证据链。
- **证据链（题面"来源证据"纪律）**：每字段挂 `{rule_name, snippet}`——命中规则名 + 原文片段，值可回溯定位（面板与推送中可见）。
- **pending 纪律（K5/K6）**：规则未命中 → `status=pending`，**无 LLM 兜底**；真值基准把"真值为 null 而 verified"记为臆测（最严重扣分项），从计分上封死侥幸路径。
- **ambiguous 纪律**：多候选并存时全部保留 `candidates` 并置 ambiguous，不静默取第一个；基准判定"真值 ∈ candidates"记对（单独计数 `ambiguous_right`）。
- **锚定纪律（M4 起既定口径）**：position/org 锚只扫标题；org 取贪心最长复合机构名 + 年份前缀剥离；position 剥"招聘<N>名"人数前缀。该口径由真值 dry-run 实证驱动修订。

## 四、快照与变更检测：字段级 diff + 去抖

**设计要点**（`src/snapshot/differ.py`，M3）：

- **字段级比较分类事件**：`content_hash` 只作"有无变更"初筛信号，**不做一票否决**——哈希变了但可比较字段未变，仍记 `content_changed`（detail 指明无字段级差异，事件不丢失）；哈希没变则不重复告警。
- **四类事件**（`EventKind` 枚举）：`new_posting / deadline_changed / content_changed / announcement_removed`。
- **删除去抖（K4，N=3）**：公告单轮缺失不判定删除，连续 3 轮缺失才产出 `announcement_removed`；期间复现记 `missed_then_reappeared`（防误报，有基准边界用例覆盖）。
- **可查询性**：SQLite 持久快照 + 事件表，任意 URL 的完整变更时间线可查（`jobsctl timeline --url` / 面板时间线页）。

## 五、订阅与推送

- 规则文件化（`subscribe.yaml`，示例入库、真实文件 git-ignored）；匹配域 = 标题 + URL + detail 值文本，关键词 AND 全命中、大小写不敏感，sources/kinds 可选过滤；**匹配是纯函数**，同输入恒定输出（测试断言）。
- RSS 2.0 与 HTML 摘要均为标准库手写（`xml.sax.saxutils.escape` 转义、属性序固定），GUID = sha256(kind|url|round|detected_at) **同事件恒定**（重复运行不产生重复推送项）。
- **K6 门控在 feeds 层收口**：进入推送的 detail 只含 verified 字段值（differ 产出时已门控，feeds 层有测试断言"pending 不出镜"）。

## 六、基准口径与当前指标

详见 [bench/README.md](../bench/README.md)（权威口径）。摘要：

- **真值抽取基准**：`bench/fixtures/truth.json` v1 27 例（真实列表页条目 + deadline 句式样例 + 分类样例），人工标注挂 `url + annotated_at + 字段级 evidence`。判定：真值 null → pending 对、verified/ambiguous 记错（臆测扣分）；非招聘条目不入字段分母；相对期限样例 pending 正确不计分母。
- **变更检测基准**：3 用例 11 期望，多轮受控构造走 `SnapshotPipeline` 生产路径（不是旁路模拟），期望"消费"语义防重复计数。
- **可证伪探活**：测试运行时删一条 deadline 规则 → 基准必须报未达标（基准失效等价于质量保障失效，绝不允许）。
- **当前指标（2026-10-14）**：overall 108/109 = **99.1%**（position 95.5%，唯一扣分项为『<实验室>主任招聘公告』句式未覆盖，诚实保留、`jobsctl bench` 退出码 1 不隐藏）；其余 4 字段 100%；分类 5/5；变更样本 11/11 检出、零误报。

## 七、双形态对账（CLI ⧉ Web 面板）

**单一事实源**：`src/webapp/views.py` 是共享视图层——CLI（`timeline/feed/bench` 打印）与面板路由（`/timeline /subscribe /bench`）都从这里取数；订阅匹配复用 `subscribe.match_events` 纯函数，基准直接渲染 `bench.run_truth / run_change_cases` 报告对象，**任何一侧都不重复实现查询/判定逻辑**。

**三方对账测试**（`tests/test_m5_webapp.py`）：同一 tmp 快照库上断言 CLI stdout = 直调视图函数 = 面板渲染（时间线事件集合一致、订阅命中数一致、基准数字一致）。面板纪律：零外链内联单页（断网可演示）、`/docs` 关闭、只读不改库（字节级断言）、空库优雅渲染。

## 八、合规红线（全程有效）

1. robots + 限频（≥3s）+ UA 自标识；WAF 识别即隔离，不绕过；
2. 仅缓存公开公告元数据，不存整页镜像（raw 只落 git-ignored `cache/`）；
3. 不采集个人信息：联系人姓名/电话不入结构化字段库、不进推送；
4. 不抓登录墙内数据（清华/浙大首期不纳入，实测记录见 data/README）；
5. 合成样例单位名假名白名单（K8 自动扫描，truth.json 显式豁免——真实 URL 是标注对象，发布脱敏在 M6）。
