# 模拟项目题：高校学术招聘聚合监控器（多源人事处/招聘平台抓取 · 结构化字段抽取 · 快照与变更检测 · 截止监控推送）

> **性质**：自拟模拟项目题（不参赛，成果发布 GitHub 公开仓库）。交付形式为 **本地 Web 面板 + CLI 双形态**（Python，纯代码 + 轻量解析，基础功能零 AI 接口依赖）。
> **目标产出**：GitHub 公开仓库（本地目录 `10-15-academic-jobs-monitor`，`10-15` 为 2026-10-15 日期标签；GitHub 仓库名发布时用纯净名 `academic-jobs-monitor`，沿用系列惯例 `yuluo554/<kebab-name>`；署名 `yuluo554`）。
> **题目定稿日期**：2026-10-14
> **题目版本**：v1（首版定稿）
> **定位宣言**：招聘信息散落在几十个人事处页面上且截止日期埋在正文里——本工具做多源聚合 + 结构化字段抽取 + 变更/截止监控推送（RSS/邮件），把"盯官网"变成可复现的数据管道。持久快照与变更历史是 LLM 聊天给不了的：同一 URL 昨天 vs 今天的 diff（新增岗位 / 截止日变更 / 公告删除）只有持久化管道能回答。

## 一、项目介绍

高校教师招聘与博士招生的公告发布链路高度分散：教育部直属高校各有人事处页面（如北京大学人事部、复旦大学人事处、南京大学人力资源处），另有高校人才网（gaoxiaojob.com）、学术桥（zpjob.acabridge.cn）等聚合平台。公告正文格式各异，**截止日期往往埋在正文段落里**而非结构化字段；招聘计划、报名时间、资格条件等信息按《事业单位公开招聘人员暂行规定》（人事部令第 6 号，2006-01-01 施行）本应公开发布——公开招聘须发布招聘计划/信息/资格条件，这正是结构化字段抽取的官方依据。

求职者与博士申请者的真实痛点是三条：**①盯不过来**——每天逐个刷新几十个人事处页面不现实，漏一条心仪岗位的公告可能就是错过一个截止日；**②截止日期难找**——正文里的"报名截止 2026 年 X 月 X 日"没有统一格式，靠人眼扫读极易遗漏或读错；**③变更无感知**——岗位公告会被编辑、延期、删除，没有快照就没有历史，用户无从得知"这条公告昨天还是 12 月截止、今天改成 11 月了"。

开源侧目前**"国内高校招聘信息聚合 + 变更监控"近乎空白**（GitHub 检索 "高校招聘 聚合"/"faculty hiring scraper"/"academic job board crawler" 0 仓库；"academic jobs scraper" 9 个均为国外小工具；"高校 招聘 爬虫" 仅 gaoxiaojob_crawl 一个 1★ 个人脚本，且只做抓取、无监控无 RSS——基准日 2026-10-14，软论据 ⬜）。商业侧 jobs.ac.uk 验证了"聚合 + 邮件订阅"模式的价值但有登录墙且只覆盖英国；高校人才网有数据但无监控无 RSS。

## 二、任务要求

> 首期模块限定为 **5 个**，数据源首期限定 **5 源**（高校人才网 + 学术桥 + 北大/复旦/南大 3 所人事处）。全部模块遵循"**未核对的字段不得落库进入推送路径**"的确定性纪律：抽取字段一律带 `status`（`verified`/`pending`）与来源证据（URL + 命中规则名），不确定即标 pending，绝不臆测。

### 1）多源抓取适配器（数据底座，亮点）

- **输入**：首期 5 源的列表页 URL；**输出**：统一的原始条目模型（标题/URL/发布日期/来源站点，raw HTML 落盘留证）；
- 每源一个独立适配器（静态 HTML 解析为主），适配器间互不共享解析假设；某源失败**隔离不中断**（超时/403/解析失败单列原因码，不影响其他源本轮产出）；
- **确定性纪律**：解析规则与页面结构一一对应，解析不出整条跳过并记录，不做启发式猜测；请求带限频与 User-Agent 标识，遵守 robots；
- 已实测底座：高校人才网 ✅（可直连、静态返回；深层列表 403 反爬，首期只取可直连层级）、学术桥 ✅（初始列表服务端渲染，"加载更多" XHR 分页留扩展）、北大 ✅ / 复旦 ✅（/15364/list.htm 结构规整）/ 南大 ✅ 人事处均为静态列表。清华 ⬜（307 跳统一认证）、浙大 ⬜（拒连）首期不纳入。

### 2）结构化字段抽取（确定性内核，亮点）

- **输入**：原始条目的详情页正文；**输出**：结构化字段（岗位名称/单位/学科方向/待遇/截止日期），每字段挂抽取依据（命中的规则名 + 原文片段定位）；
- **规则优先**：正则 + 规则模板做确定性抽取（如截止日期的多格式正则族：`报名截止`、`即日起至 X 年 X 月 X 日` 等），规则命中不了即标 pending，**不用 LLM 兜底**（基础功能零 AI 依赖）；
- **确定性纪律**：同一正文输入产出恒定；一条字段多个候选值时全部保留并标歧义，不静默取第一个。

### 3）快照与变更检测（招牌模式）

- **输入**：本轮与历史轮次的条目集；**输出**：对同一 URL 的 diff 报告——**新增岗位 / 截止日变更 / 正文实质变更 / 公告删除** 四类事件；
- 持久快照（本地存储）+ 变更历史逐轮累积，可查询任意 URL 的变更时间线；
- **确定性纪律**：diff 判定基于字段级比较（非全文哈希一票否决），正文哈希仅作变更存在的初筛信号；删除判定须连续 N 轮缺失才成立，避免网络抖动误报。

### 4）订阅与推送

- **输入**：变更事件流 + 用户关键词订阅（如"XXXX大学"、“副教授”、“XX方向”）；**输出**：RSS feed 与 HTML 摘要两种形态（邮件/webhook 推送留扩展）；
- 关键词过滤在本地完成，订阅规则文件化、可版本管理；
- **确定性纪律**：同一事件在订阅规则不变时要么稳定命中要么稳定不命中；推送条目必带来源 URL 与事件类型，不夹带抽取未 verified 的字段。

### 5）内置基准（零 API 依赖）

- **抽取真值基准**：人工标注的真实公告样例（真实公告 URL + 人工标注的岗位/截止日等字段真值），逐字段统计抽取准确率，指标口径写进 README；
- **变更检测基准**：构造"同一页面两轮不同版本"的受控样本，验证四类事件的检出与不误报；
- **合成样例纪律**：合成样例的单位名一律使用**假名白名单**（如"某高校""示例大学"），不得虚构真实院校的待遇/截止数值。

### 扩展项（不计入首期 DoD）

XHR 分页源（学术桥"加载更多"接口）、需 JS 渲染源（研招网部分区块）、邮件/webhook 推送、Web 面板的订阅管理界面深化。

### 合规注意

遵守各源 robots 与限频；仅缓存公开公告的元数据（标题/URL/日期/正文抽取字段），不存储整页镜像；抓取行为带明确 UA 标识可被识别与联系。

## 六、边界与非目标

- **不做**：不做简历投递、代报名、与招聘方互动等代理行为；不做登录墙内数据采集（清华 ⬜、浙大 ⬜ 首期不纳入，待获取后再议）；不做对非公开/内部渠道信息的抓取。
- **隐私红线**：不采集个人信息（公告中的联系人姓名/电话仅作原文定位引用，不入结构化字段库、不出现在推送摘要）；缓存仅限公告元数据，不存整页镜像。
- **合规红线**：遵守 robots 与限频；抓取器 UA 自标识；输出免责声明：推送与抽取结果仅供参考，**报名截止日期等以招聘单位官方公告原文为准**，不构成求职建议。
- **品牌隔离**：不复制姊妹项目代码；文档不提其余项目业务领域。
- **首期范围限定**：5 模块 + 5 源；XHR 分页、JS 渲染源、邮件/webhook 均为扩展项，不计入首期 DoD。
