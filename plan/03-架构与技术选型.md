# 03 — 架构与技术选型

> 依据：[01-题目文档.md](01-题目文档.md) v1 与 [00-README总览.md](00-README总览.md) 决策记录。骨架已按本文落地（commit 304caaf + 纪律修复提交）。

## 一、技术选型（与零 AI 依赖纪律对齐）

| 项 | 选型 | 理由 |
|---|---|---|
| 语言/版本 | Python ≥ 3.10（开发机 3.12.10；本机另有 3.8 通道） | CI 矩阵 3.10/3.12；枚举用 str 混入 `_StrEnum`（`enum.StrEnum` 是 3.11+，3.10 会挂——M0 实测修） |
| HTTP | httpx | 纯静态抓取；同步模型足够，`timeout`/UA/限频单点收敛在 `fetch.Fetcher` |
| 解析 | BeautifulSoup4 + lxml | 五源均静态 HTML；适配器只依赖各自选择器，互不共享解析假设 |
| 存储 | SQLite（标准库）+ raw HTML 文件落盘 | 单文件可审计；快照 diff 用 SQL；不存整页镜像（合规） |
| RSS | 标准库手写 RSS 2.0 XML | 零重依赖，输出可控 |
| Web 面板 | FastAPI + 内置静态页（零依赖内联单页优先，无 vendor 无外链） | 面板只渲染引擎结果、零判定逻辑；`/docs`、`/redoc` 显式关闭（Swagger UI 引 CDN） |
| CLI | argparse 子命令（标准库） | `jobsctl crawl/extract/snapshot/feed/bench/web` |
| 测试 | pytest + fixtures（落盘样本 HTML，全离线） | CI 无需真实站点 |
| CI | GitHub Actions：ruff + pytest 3.10/3.12 | 评分项"测试与 CI"；env `PYTHONUTF8=1` + `fetch-depth: 0` 已配 |

**刻意不引入**：LLM/任何 AI 接口（基础功能零依赖）、scrapy（框架过重且削弱"适配器互不共享解析假设"）、前端框架（面板职责仅渲染）。

## 二、分层架构

```
CLI (jobsctl)          Web 面板 (FastAPI)          ← 双入口，只渲染不判定
        └──────────┬──────────┘
              引擎层 ajm
  sources/    →   extract/   →   snapshot/   →   subscribe/
  5源适配器       规则抽取       快照diff        订阅匹配+RSS
  (失败隔离)      (status门控)   (四类事件)      (仅verified出镜)
        └──────────┬──────────┘
          fetch.py (UA/限频/超时)   storage.py (SQLite)   bench/ (真值+受控基准)
```

- **单一事实源**：CLI 与 Web 共用同一编排函数组（M5 落地时上收成 `pipeline` 公开函数，行为等价用三方对账测试：CLI stdout = 编排直调 = 面板渲染，断言行为而非"都调了同一函数"的字面声明）。
- **失败隔离单点**：`sources/registry.py` 逐源 try/except 兜底；单源异常只产生 `FailureCode`，不中断其他源（骨架期已有测试锁死）。
- **status 门控单点**：`ExtractedField.status ∈ {verified, pending}`；推送路径模型层只接受 verified。

## 三、确定性纪律的骨架落点（评分核心）

1. **status 门控**：枚举而非字符串约定（`config.py`）；`feeds.py`（M4）在模型层只接受 verified 字段。
2. **失败隔离**：`FetchOutcome(ok | failure(code, detail))` + registry 逐源兜底；原因码 `TIMEOUT/HTTP_403/PARSE_EMPTY/...` 单列。
3. **解析不出即跳过**：适配器契约规定"解析不出整条返回并登记原因"，禁止启发式猜测（无兜底正则）。
4. **字段级 diff**：`differ.py`（M3）对 `JobPosting` 逐字段比较；`content_hash` 仅作变更初筛信号；删除判定连续 N=3 轮缺失去抖。
5. **假名白名单**：`FAKE_ORG_WHITELIST` 枚举登记（`某高校/示例大学/示例研究院/示例学院/某研究院`）；M4 加 lint 测试扫描 fixtures 不得出现真实院校名。
6. **合规内建**：UA 自标识（项目名+仓库 URL+联系邮箱占位）、每源 ≥3s 限频、仅缓存公告元数据、README 免责声明。

## 四、目录结构

见仓库树；核心映射：`src/ajm/{config,models,storage,fetch}.py`（已实现）→ `sources/{base,registry}.py`（已实现，5 适配器 M2 落地）→ `extract/ snapshot/ subscribe/ bench/ webapp/`（M3–M5 逐个填充）。

## 五、既定口径（动了会打挂基准/测试的约定，随里程碑累积）

- K1 枚举基类用 `_StrEnum`（str 混入），不迁 `enum.StrEnum`（3.10 兼容底线）。
- K2 CI 必带 `PYTHONUTF8=1` env + 所有 checkout `fetch-depth: 0`。
- K3 CLI 入口必有 `_ensure_utf8_stdio()`；新增可打印脚本（tools/ 等）一律同款守卫。
- K4 限频下限 3s/源、删除去抖 N=3 轮——改这两个数属口径变更，须登记决策记录并同步测试。
