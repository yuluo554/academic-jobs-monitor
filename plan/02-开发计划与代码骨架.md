## 一、技术选型（与零 AI 依赖纪律对齐）

| 项 | 选型 | 理由 |
|---|---|---|
| 语言/版本 | Python ≥ 3.10（开发机 3.12.10） | `dataclass(slots=True)`、`X | Y` 类型语法；面向 GitHub 受众的常规底线 |
| HTTP | httpx + (可选) lxml/BeautifulSoup4 解析 | 纯静态抓取；同步模型足够，`timeout`/UA/限频内建 |
| 解析 | BeautifulSoup4 + lxml（容错性好） | 五源均为静态 HTML；适配器只依赖选择器，不共享解析假设 |
| 存储 | SQLite（`sqlite3` 标准库）+ raw HTML 文件落盘 | 单文件可审计、可 git-ignored；快照 diff 直接用 SQL；不存整页镜像（合规） |
| RSS | 标准库手写 RSS 2.0 XML | 零重依赖，输出可控 |
| Web 面板 | FastAPI + 内置静态页（无前端框架） | 面板只渲染引擎结果、零判定逻辑（评分标准约束） |
| CLI | argparse（标准库子命令） | `jobsctl crawl/extract/snapshot/subscribe/feed/bench/web` |
| 测试 | pytest + 内置 fixtures（落盘样本 HTML） | 离线可跑，CI 无需真实站点 |
| CI | GitHub Actions：ruff + pytest（3.10/3.12 双矩阵） | 评分项"测试与 CI" |

**刻意不引入**：LLM/任何 AI 接口（基础功能零依赖，评分红线）、scrapy（框架过重且削弱"适配器互不共享解析假设"）、前端框架（面板职责仅渲染）。

## 三、确定性纪律的骨架落点（评分核心，先行内建）

1. **status 门控**：`ExtractedField.status ∈ {verified, pending}` 是 `models.py` 的枚举而非字符串约定；推送路径（`feeds.py`）在模型层只接受 `verified` 字段。
2. **失败隔离**：`sources/base.py` 定义 `FetchOutcome(ok | failure(code, detail))` 结果类型 + `registry.py` 逐源 try/except；某源异常只产生 `FailureCode`（`TIMEOUT/HTTP_403/PARSE_EMPTY/...`），不污染其他源本轮产出。
3. **解析不出即跳过**：适配器契约规定"解析不出整条返回 `None` 并登记原因"，禁止启发式猜测（无兜底正则）。
4. **字段级 diff**：`differ.py` 对 `JobPosting` 逐字段比较；`content_hash` 仅作"是否有变更"初筛，不作为事件分类依据。删除判定：连续 N 轮（默认 3）缺失才产出 `ANNOUNCEMENT_REMOVED`。
5. **假名白名单**：`bench/fixtures` 生成器与合成样例只允许 `FAKE_ORG_WHITELIST = {某高校, 示例大学, 示例研究院, ...}`（`config.py` 枚举登记）；CI 中加一条 lint 测试扫描 fixtures 中不得出现真实院校名。
6. **合规内建**：`fetch.py` 统一 UA（含项目名+仓库 URL+联系方式占位）、每源默认限频（≥3s 间隔）、仅缓存公告元数据 + raw 留证不外发；README 免责声明模板已在骨架 README 占位。

## 四、里程碑执行计划（对齐 00-总览 M2–M6）

### M2 抓取底座（5 源适配器）
- 每个 adapter 一个文件，输入列表页 URL → 输出 `RawItem` 列表（标题/URL/发布日期/来源）；raw HTML 落 `cache/raw/<source>/<date>/` 留证（git-ignored）。
- 解析器逐源对照真实页面选择器编写（先人工看页面结构，不臆测）；每源配一个用真实结构回放的离线 fixture 测试。
- `cli.py crawl`：`--source all|<id>`，输出本轮各源条目数/失败原因码汇总表。
- DoD：5 源各至少 1 轮真实抓取成功 + 失败隔离演示（手工断网一源验证其余 4 源照常）+ 离线测试绿。

### M3 抽取与快照（招牌模式）
- `rules.py`：截止日期正则族（`报名截止`、`即日起至X年X月X日`、`X月X日截止`…每条规则命名登记，命中即附规则名+原文片段）；岗位/单位/待遇规则模板同法。
- `pipeline.py`：单字段多候选 → 全保留 + `ambiguous` 标记；规则未命中 → `pending`。
- `storage.py` 快照入库；`differ.py` 字段级 diff → 四类事件（`NEW_POSTING / DEADLINE_CHANGED / CONTENT_CHANGED / ANNOUNCEMENT_REMOVED`）+ 变更时间线查询。
- DoD：受控两轮样本四类事件全部正确检出且无误报；字段抽取对 fixtures 真值初测。

### M4 基准与订阅
- 人工标注真值库（真实公告 URL + 标注 JSON，逐字段）；`bench` 一条命令出逐字段准确率报告，**指标口径写进 README**（按 verified 候选命中即算对的口径明确化）。
- 变更检测基准：构造两轮版本受控样本（含截止日改期、公告删除后复现等边界）。
- `matcher.py` + `feeds.py`：关键词订阅规则文件（`subscribe.example.yaml` 入库，真实订阅 git-ignored）；RSS + HTML 摘要；一致性验证（同事件同规则重复运行命中结果恒定）。
- DoD：`jobsctl bench` 可重复运行；`examples/` 有样例 RSS。

### M5 交付形态
- `webapp/app.py`：本地面板（条目列表 / 变更时间线 / 订阅预览 / 基准报告页），**只调用引擎函数渲染结果**。
- CLI 与面板共享同一引擎层，验收标准=双入口对同一数据产出一致结论。
- `docs/技术报告.md`（适配器设计、规则族、diff 判定方法）；README 终稿（演示截图、指标口径、免责声明）。
- DoD：双入口一致性手测记录入档；README 含截图。

### M6 发布
- 脱敏审查（`scripts/release_checklist.py`：扫描真实订阅文件/个人信息/raw 缓存不入库；免责声明与 UA 在位；假名白名单合规）。
- git tag（如 `v0.1.0`）→ push GitHub 公开仓 `yuluo554/academic-jobs-monitor` → Release 附演示截图 + 样例 RSS。
- 发布留档三件套（发布记录回写 plan/）。

## 五、风险与预案

| 风险 | 预案 |
|---|---|
| 某源页面结构变化导致解析失效 | 适配器解析不出即整条跳过并记录原因码（契约保证）；fixture 测试定位是选择器漂移还是站点改版 |
| 高校人才网详情页截止日期需二级抓取易触 403 | 二级抓取单独限频 + 退避；失败标 `pending` 不阻塞主列表 |
| 学术桥 XHR 分页 | 首期只取服务端渲染初始列表；分页接口留扩展（题面明确不计 DoD） |
| 真值标注工作量 | 标注对象限定为公开公告的 5 个字段；每源先标 5–10 条滚动补充 |
| Windows 路径/编码 | 全项目 `pathlib` + 显式 `encoding="utf-8"`；CI 加 windows-latest 矩阵（视 runner 配额，至少 ubuntu 覆盖） |
